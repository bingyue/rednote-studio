# GOAL｜RedNote Studio：面向个人创作者的小红书 AI 创作工作台

> 使用方式：将本文完整交给 Codex / Claude Code / AI 编程 Agent，在本地工作目录直接执行。目标是一次性完成可运行、可点击、可测试、可演示的生产 Demo 级项目，而不是仅编写方案、空壳页面或静态设计稿。无需等待用户逐条确认非关键细节，应采用下文约定的合理默认值并记录取舍。

## 0. 一句话产品定义与最终目标

你是一支由资深产品经理、个人创作者增长顾问、全栈工程师、AI Agent/Skill 工程师、浏览器扩展工程师、UI/UX 设计师、测试工程师和隐私合规专家组成的虚拟团队。

开发 **RedNote Studio（小红书 AI 创作工作台）**，一句话定位：**一个人的小红书 AI 内容团队**。

服务对象：个人创作者、个人 IP、自由职业者、1–5 人轻量内容团队。帮助用户在一个工作台完成：**灵感/选题 → AI 创作 → 文案与封面编辑 → 敏感词与内容检查 → 选择账号 → 发布辅助 → 记录发布结果**。

产品不是企业 CRM、不是聚光投流管理平台、不是批量群控系统、不是通用工作流平台，也不是完整指纹浏览器。必须保持小而完整。

### 无条件优先的验收目标

1. **4 个一级工作台**：创作、Skills、发布、账号；素材、灵感、风格、设置为子功能，保持主导航极简。
2. **8 个高频 Skills**：爆款拆解、选题生成、标题优化、笔记写作、封面排版、内容合规检查、小红书 SEO、个人风格改写。所有 Skill 都可真正运行（无 Key 时走可复现 Mock），并能把结果应用到当前稿件。
3. **1 条端到端完整闭环**：创建笔记 → 生成/编辑 → 敏感词检查 → 制作封面 → 保存草稿 → 选择账号 → 创建发布任务 → 通过人工/浏览器辅助发布 → 填写真实发布链接并确认 → 进入历史作品。
4. **1 套账号工作环境管理器**：记录自有/已获授权账号，关联用户本地独立浏览器 Profile，支持手动登录、一键打开创作者后台、检查是否需要重新登录。不得实现账号盗取、伪造指纹、批量绕过风控。
5. **两个可交付的 UI**：正式可运行 React 前端，以及 `/prototype/index.html` 单文件、高保真、脱离服务器仍可交互的 HTML 原型。
6. **项目交付工程化**：README、docs 文档体系、数据模型及迁移、测试、Demo 数据、脚本、Docker Compose、后端 API、浏览器扩展/本地助手（详见后文）。

原则：优先保证完整闭环和优质交互；不把开发资源浪费在企业多租户、营销投流、私信 CRM、数字人、自动刷互动、重型多 Agent 平台。

## 1. 用户画像与使用场景

### 1.1 三类主要用户

- 单账号个人博主：每周写 3–7 篇笔记，需要快速选题、文案、封面、合规检查。
- 多账号创作者：拥有 2–5 个本人或授权管理的账号，希望不同账号有独立内容风格、草稿与浏览器会话。
- 轻内容团队：策划、编辑、发布各有角色，但不需要复杂审批流，支持 1–5 人分享素材与草稿。

### 1.2 五个关键故事

A. 我有一个想法，10 分钟内完成一篇能发布的图文笔记。

B. 我找到一篇参考笔记（用户粘贴文字、自己有权使用的素材，或通过合法接口导入），用拆解 Skill 提炼结构，再生成原创文章，而不是抄袭。

C. 我在发布前检查标题、正文、话题以及封面中文字的风险；展示具体问题、上下文和改写建议，而不是输出不可信的“保证过审”。

D. 我在多个自己管理的账号之间切换，确保每个账号的定位、草稿和本地登录环境清晰隔离。

E. 我完成内容后，以人工确认或明确获准的浏览器辅助方式发布，并将作品链接、发布日期和手动导入的表现数据关联回作品。

## 2. 严格产品边界

### MUST（第一版必须实现）

- 单用户本地优先，也支持创建可选轻团队工作区；账号资料不跨用户泄露。
- 统一图文笔记编辑器：标题、正文、话题、卡片式封面、多图素材、预览、草稿自动保存、版本恢复。
- 8 个可调用 Skills，支持从当前笔记上下文执行并一键应用（同时保留原版本）。
- 规则词典 + 上下文 AI 辅助的内容合规检查，支持维护自定义风险词库、风险等级和人工忽略理由。
- 模板化封面生成与导出；基于 Canvas/SVG/HTML 渲染，模板、配色、尺寸、文字、背景图可编辑。
- 账号档案、账号定位/风格、账号与草稿关联、浏览器工作环境配置。
- 草稿列表、待发布列表、轻量日历、发布准备检查、发布任务、手动发布确认、历史记录。
- 可靠的演示数据模式（无外部凭据时可以完整体验）。

### SHOULD（尽量实现，不影响主闭环）

- 轻量灵感收集箱、关键词与个人知识素材库、风格样例上传。
- Chrome Manifest V3 扩展：从当前稿件发起复制/导出/打开创作页辅助操作；敏感页面上只在用户明确点击和授权后执行。
- 本地桌面小助手：独立 Chrome Profile 的可视化创建/打开，不将 Cookie 发送到云服务；若环境不能安装本地 app，交付独立可运行 CLI 与前端深链/操作说明。
- CSV 形式手动导入笔记表现数据（浏览、点赞、评论、收藏、涨粉）并进行简单复盘。
- 轻团队草稿共享、评论和状态，无复杂组织权限树。

### WON'T（禁止范围膨胀）

- 企业 CRM、聚光投流系统、付费广告账户管理、跨境电商、数字人平台、完整视频剪辑器。
- 大规模多账号群控、批量创建账号、自动刷赞刷评刷收藏、骚扰私信、账号买卖、绕过验证码/封禁/速率限制。
- 设备指纹伪装、浏览器指纹欺骗、代理 IP 轮换规避检测、持久化明文 Cookie 收集、私有接口逆向抓取作为发布主链路。
- 未获授权时声称通过官方 API 实际发布、自动同步笔记数据或真实监控账号在线。
- 大而全的 Skill Marketplace、复杂 DAG 编辑器、低价值营销数据图表。

## 3. 整体交互：创作页即首页

4 个一级导航：**创作｜Skills｜发布｜账号**。右上角有账号切换、素材库入口、个人设置；底部可访问帮助与扩展连接状态。

### 3.1 创作工作台 `/create`

桌面采用三栏可折叠布局：

- 左栏（240px）：最近草稿、灵感收件箱、账号定位、素材与内容模板。
- 中栏（自适应）：文章标题、富文本/Markdown 正文、标签输入、图文卡片、封面预览、保存与版本历史、草稿预览。
- 右栏（320px）：快捷 Skill 区、执行结果、风险标记、改写对比；可一键替换标题/正文片段或保留建议。

顶部展示当前稿件绑定账号、自动保存状态、合规状态和“准备发布”按钮。

**编辑器细节**：
- 标题字数及正文长度提示，规则来源可配置，不硬编码为平台永久限制。
- 允许 Markdown 输入与预览、常用富文本操作、emoji、话题标签。
- 支持自动保存防抖、草稿版本快照、撤销/恢复、离开页面未保存提醒。
- AI 输出总是先预览 diff 再应用；提供撤销以及“保留原稿”。
- 封面素材可上传、裁切、切换模板、调整主副标题、字体、字号、背景和安全区域，可输出 PNG。
- 真实发布前执行检查：文案完整性、图片、授权账号、敏感内容、确认最终稿。

### 3.2 Skills 工作台 `/skills`

按“策划”“写作”“设计”“优化与合规”四类展示 8 个 Skill 卡片。点击卡片打开输入表单，支持“从当前草稿读取上下文”“单独运行”“应用结果”。展示耗时、费用估算（若模型返回用量）、历史输出、重试、提示词版本。

8 个 Skills 精确定义：

1. `viral_deconstruction`：输入参考笔记内容；输出开场钩子、结构拆解、受众需求、可借鉴表达方法、原创化方向；严禁整篇照搬原作。
2. `topic_ideation`：输入赛道、粉丝画像、最近选题、目标；输出 10 条选题、切入点、核心关键词、建议内容形式。
3. `title_optimizer`：输入正文或现有标题；输出 5 种不同角度标题、特点、注意事项。
4. `note_writer`：输入主题、目标人群、风格和要点；输出标题、正文、话题建议、封面文案与配图建议。
5. `cover_designer`：输入标题、主视觉、模板；返回可编辑封面配置和导出 PNG，不接受只有“生成图片成功”却没有文件。
6. `compliance_review`：输入标题、正文、标签、封面文字；规则词库先判定 + AI 上下文判定；返回位置、文本片段、风险类型、证据/依据、风险级别、建议改写、需人工复核标记。OCR 可选、非必需；图片文字可以先通过用户输入或编辑器已知文字获取。
7. `seo_optimizer`：输入笔记、领域关键词；输出搜索意图、主/次关键词、自然嵌入建议、话题建议，不承诺排名。
8. `style_rewriter`：输入作者**自己的**历史样本、当前内容；输出风格画像、改写版本和差异说明，避免侵犯第三方作者权益。

Skill 契约需要标准化：`id`, `version`, `name`, `category`, `input_schema`, `output_schema`, `executor`, `capabilities`, `timeout`, `requires_ai`, `status`。Skill Engine 统一验证输入输出、记录执行日志，不能让用户自定义文本成为系统指令或执行任意代码。支持固定组合模板“选题→文案→标题→合规→封面”，暂不研发自由拖拽流程编排器。

### 3.3 发布工作台 `/publishing`

包含列表视图、周历视图，状态：`DRAFT`、`READY`、`SCHEDULED_REMINDER`、`PUBLISHING_ASSISTED`、`PUBLISHED_CONFIRMED`、`FAILED`、`CANCELLED`。排期表示**定时提醒**，不等于后台自动发布。展示目标账号、预计日期、封面、状态、发布链接、操作者、最后更新时间。

提供三种适配器设计：

- `ManualPublisher`（默认可用）：复制标题正文、下载素材、打开小红书官方创作页面、用户操作后粘贴链接确认。
- `BrowserAssistPublisher`（有明确授权与可行性验证后实验启用）：浏览器扩展在用户当前授权页面上辅助填写或附加素材，最后由用户确认提交；不绕过平台限制。
- `OfficialPublisher`（预留接口）：只有获得真实官方发布 API 授权、实际验证 endpoint 后才可实现与启用；不得捏造接口。

每次发布执行须记录 task_id、账号、内容版本、用户、时间、状态和错误；提供防重复发布确认。没有实际发布成功的证据，不允许显示“发布成功”。

### 3.4 账号工作台 `/accounts`

支持本人或明确授权账号的账号档案（昵称、头像、类别、账号定位、主要话题、风格样本、工作环境别名、发布次数）。关联本地 Chrome Profile，由本地助手执行“一键打开对应浏览器窗口”；默认由用户本人扫码或正常登录。

- 每个 Profile 独立数据目录，隔离 Cookie / localStorage / 会话；不读取、上传或明文导出认证 Cookie。
- Web 服务只管理 Profile 昵称/本地引用 ID，绝不远程获取浏览器机密。
- 显示连接状态时仅可使用本地助手提供的可验证状态，不猜测“账号正常/已登录”；可显示“未检测/需人工检查”。
- Profile 创建与删除需要用户确认；删除数据目录前必须有二次确认和路径校验。
- 多账号切换不会自动开启隐藏浏览器或并发批量操作。

## 5. 技术架构（精简优先）

默认使用：

- **Frontend**：React + TypeScript + Vite + Tailwind CSS + shadcn/ui，TanStack Query，React Router，Zustand；编辑器建议 TipTap 或成熟 Markdown 编辑器；封面使用 HTML Canvas / SVG。
- **Backend**：Python 3.12+ + FastAPI + SQLAlchemy 2 + Pydantic 2 + Alembic。
- **数据库**：本地默认 SQLite（零配置运行）；支持通过 `DATABASE_URL` 切换 PostgreSQL（小团队部署）。不要为 MVP 强依赖 Redis/Kafka/微服务。
- **文件**：本地对象文件目录（dev）+ 可切换 S3 兼容存储（team）。上传文件限制类型/体积并采用随机文件名。
- **AI**：OpenAI-compatible LLM 适配器 + 纯本地确定性 MockProvider（无 Key 可演示），支持结构化输出、超时、重试、错误可见、Token 用量记录。
- **浏览器扩展**：Chrome MV3，严格最小权限，功能仅限当前用户触发的辅助复制/导出/打开工作流；任何 DOM 交互均需权限和页面规则审核。
- **本地 Profile 助手**：优先 Python CLI 或 Node CLI 管理独立、合法的 Chrome 浏览器 Profile；若能实现轻量本地服务需绑定 loopback、启用随机 session token、CORS 限制、命令白名单，避免任意文件路径与远程代码执行。
- **部署**：开发模式 `make dev`，容器模式 `docker compose up --build`，前端、后端可运行；Profile 助手为本机独立进程而非服务器远程执行。

## 6. 数据库与 API

最小实体：

- `User`, `Workspace`, `WorkspaceMember`（个人默认一个 Workspace，最多 5 人协作扩展）。
- `CreatorAccount`（自有/授权来源字段）, `BrowserProfileRef`, `CreatorStyleSample`。
- `Post`, `PostVersion`, `PostTag`, `PostAsset`, `ContentTemplate`, `Idea`, `Asset`。
- `SkillDefinition`, `SkillRun`, `AIUsageRecord`, `ComplianceRule`, `ComplianceFinding`, `ReviewDecision`。
- `PublishTask`, `PublicationRecord`, `ScheduleReminder`, `PostMetricImport`。

统一 UUID、UTC 时间、FK 与索引；正文的版本历史不可只覆盖字段。多账号资料、草稿、工作区数据必须按用户权限过滤。不要存明文 API Key、账号密码或浏览器 Cookie；AI 模型密钥使用后端环境变量或加密的本地秘密存储。

API 前缀 `/api/v1`；统一错误格式 `{code, message, details, request_id}`。至少实现：

GET/POST  /accounts
GET/PATCH /accounts/{id}

GET/POST  /assets

所有写操作应使用后端持久化，不得只靠 localStorage 假装有数据库。文件上传使用安全路径处理与类型校验；发布确认需要真实链接和用户操作。通过明确的 Mock 模式构造完整 API 示例。

## 7. 合规检测 Skill 是必须打磨的重点

实现“规则引擎 + 可选 AI 上下文审核 + 结果解释 + 人工确认”四层。可自定义词库，按以下类型分类：

- 绝对化表述与无法证实的保证。
- 广告效果/收益承诺。
- 医疗、药品、保健、美容等高敏感主张。
- 教育培训、金融投资等特定行业的受限承诺。
- 站外引流和平台营销规则风险（按现行官方规则校验）。
- 版权、肖像、隐私及误导性内容提示。

输出 JSON 至少包含 `rule_id`, `span_start`, `span_end`, `matched_text`, `risk_type`, `severity`, `explanation`, `suggestion`, `review_required`, `source_type`。需要在编辑器中高亮对应文字，并提供“采用建议”“忽略并记录原因”；检查结果与稿件版本绑定。

**重要**：敏感词命中并不天然代表违法，漏检也不代表合法；产品应使用“风险提示/建议复核”，而不是“必过审”“不被限流”。参考规则和词库须标注维护日期及来源，提供管理员更新入口。

## 8. AI 系统工程要求

- 提示词按 Skill 版本化，输入输出符合 JSON Schema / Pydantic Schema，失败有重试、可审计错误状态。
- AI 生成内容不能直接执行系统命令、数据库 SQL 或平台发布动作。
- `MockProvider` 对每个 Skill 都必须给出结构化且看起来合理的演示结果，不以返回固定一句“生成成功”充数。
- 模型真实调用通过后端代理，前端不能直接暴露秘密 Key。
- 每次结果可预览、可接受、可拒绝、可编辑；支持对比与撤销。
- 文案生成明确要求原创表达、避免照抄参考笔记及未验证事实。
- 系统提示词与参考笔记、网页、粘贴材料隔离；把后者当作不可信文本。
- 允许用户为账号保存受众、语气、禁用词、常用话题与内容边界，生成时自动注入其作为普通配置。

## 9. 单文件 HTML 原型验收

生成 `prototype/index.html`，本机双击即可打开，不依赖 CDN/网络。要求具有：

- 左侧 4 个主入口导航、顶部账号切换、创作三栏编辑器。
- 8 个 Skill 真实可点击，使用本地 mock 数据模拟调用；触发后能改变界面内容。
- 可编辑标题与正文，敏感词高亮示意，点击建议能改写对应内容。
- 封面模板可切换、主标题可编辑、可预览导出（如果 canvas 实现成本可控）。
- 发布任务列表、状态切换、内容日历和账号卡片。
- 创建/保存/编辑草稿可使用浏览器 localStorage **仅作为该单文件原型演示的本地数据层**；正式应用必须使用后端数据库。
- 窄屏响应式、暗示真实 UI 状态，避免超过 10 个无效示意按钮；重要交互全部有模拟实现。
- 在显著位置标记“交互原型 / 演示数据”，不得声称真实调用平台。

## 10. 测试、质量与验收

必须完成自动化测试，尽可能在最终交付前亲自执行并记录命令和结果：

### Backend（pytest）

### Frontend（Vitest/Testing Library）
